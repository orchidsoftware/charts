# Унификация исходников и размер бандла

Дата: 6 сентября 2026.

Это авторская матрица позиций: ведущий критерий — прямой, понятный API и практичная простота реализации, выбранные пользователем для ревью «под руководством Тейлора Отвелла». Отвелл не участвовал в ревью; утверждения не приписываются ему. Оценка основана на исполняемом коде, импортах и передаче данных, без оценки docblock.

## Матрица решений

| ------------------------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| `BuilderArguments`: named/unnamed/object dataset | Три формы входа должны сходиться в один путь                             | Копирование, цвет и callback определяются один раз                         | Удаляются два почти одинаковых разбора                                                                | Реализован единый `datasetArguments`                                                                                  |
| `BuilderArguments`: marker/region                | Отличается поле данных и набор методов callback                          | Общий разбор аргументов, явные `MarkerBuilder`/`RegionBuilder`             | Удалено повторение выбора positional/object/color/callback                                            | Реализован `annotationInput`, сохранены именованные точки входа                                                       |
| `Builder` + `TemporalBuilders` + `BuilderScopes` | Один способ применения tooltip                                           | Область callback задаёт допустимые методы; общий код применяет результат   | Три сценария применения заменяются одним; базовый temporal builder больше не наследует series tooltip | Согласовано с параллельной задачей: `builderTooltip`, tooltip в `SeriesChartBuilder`                                  |

| `CartesianRendering`                             | Одноразовому линейному проходу не нужен объект с тремя приватными полями | Порядок вызовов виден в одной функции                                      | Удалена оболочка класса; выигрыш ограничен                                                            | Реализован `renderCartesianChart`                                                                                     |

| `CartesianAxesRenderer` + annotations            | Оси и пользовательские аннотации имеют разные обязанности                | Разделение упрощает поиск, но увеличивает число файлов                     | Само перемещение методов в файл не уменьшает пакет                                                    | Выделение выполнено параллельной задачей; не считать его самостоятельной экономией                                    |
| `BuilderValidation` + `Options` + `SeriesData`   | Одно предметное правило желательно определять один раз                   | У fluent-вызова и готовой модели разные границы проверки                   | Общая схема всех семейств может притянуть лишние правила в каждый график                              | Унифицировать конкретные правила; не вводить универсальную схему без сравнительного замера                            |
| `BuilderScopes`                                  | Явные методы проще динамической генерации прототипов                     | Важно сохранить запрет неподдерживаемых методов и истечение callback scope | Генератор методов может сократить исходник, но ухудшить исключение кода                               | Сохранить явные классы возможностей                                                                                   |
| `Chart`, `InteractionController`, `ChartTooltip` | Общий жизненный цикл и доступность оправданы                             | Разделение владения DOM, событиями и выбором помогает сопровождению        | Эта функциональность составляет общий минимум любого графика                                          | Не удалять ради цифры размера; отдельный статический режим потребует отдельного продуктового контракта                |

## Что именно изменилось в связях

Ранее обе фабрики `createSeriesModel` и `createCompositionModel` вызывали `normalizeSeries`, который безусловно вызывал `normalizeCartesianSource`. Поэтому даже pie проходил через модуль нормализации markers/regions.

Теперь общая нормализация возвращает только `datasets` и `labels`. Cartesian-фабрика отдельно нормализует аннотации. Composition-фабрика сохраняет пустые `yMarkers`/`yRegions`, необходимые существующему доступному описанию, без вызова нормализатора. Внешние формы данных, выбор точки, `renderData`, форматирование и fluent API сохраняются.

## Как считать результат

Базовый замер этой задачи: полный пакет с CSS — **100,8 кБ raw / 30,4 кБ gzip**; LineChart — **20,78 кБ gzip**, MixedChart — **21,79 кБ**, PieChart — **16,55 кБ**, HeatmapChart — **12,52 кБ**. Это рабочая копия с уже существовавшими незакоммиченными исправлениями, а не чистый HEAD.

Замер выполняется `npm run build`: реальная consumer entry импортирует именованные определения из публичного пакета и CSS; сборка минифицируется, JS и CSS сжимаются gzip level 9. Sourcemaps в размер не входят. Размер `dist/index.js` в одиночку не представляет размер графика: пакет сохраняет модули.

В каталоге параллельно работала задача «Провести аудит архитектуры кода». Итоговый замер включает обе серии изменений. Его нельзя приписывать только изменениям этой задачи. Перенос методов между файлами, удаление комментариев и сокращение количества исходных строк не считаются доказательством уменьшения загрузки.

Дополнительно выполнено сопоставимое измерение напрямую из исходников: неизменяемый снимок начала задачи и текущая рабочая копия, одинаковая минификация, CSS и gzip level 9. Оно не проходит через промежуточную минификацию `dist`, поэтому его абсолютные значения немного отличаются от `npm run build`.

| Consumer entry        |   До, raw | После, raw | До, gzip | После, gzip | Изменение gzip |
| --------------------- | --------: | ---------: | -------: | ----------: | -------------: |
| PieChart + CSS        |  52 499 Б |   49 896 Б | 16 704 Б |    16 045 Б | −659 Б (−3,9%) |
| Все определения + CSS | 101 258 Б |  100 579 Б | 30 509 Б |    30 568 Б | +59 Б (+0,19%) |

Это общий результат двух параллельных задач на момент замера. **Полный пакет существенно меньше не стал.** Повторяющиеся последовательности хорошо сжимаются gzip; устранение повторений исходника не даёт пропорционального уменьшения сжатого кода. Для PieChart удаление ненужной зависимости даёт измеримую экономию.

Промежуточный замер около 29,4 кБ gzip не используется: он был выполнен при пересечении правок, когда вызовы рендера аннотаций отсутствовали. Уменьшение размера за счёт потери поведения не является результатом рефакторинга.

## Проверки

- Прямая проверка фабрик моделей через Node: все пять composition-типов сохраняют точки и отвергают неподдерживаемые markers; Cartesian сохраняет marker и нормализует обратный region.range.
- ESLint для `ChartData.js` прошёл.
- Первый общий браузерный прогон пересёк изменения файлов во время выполнения и не используется как окончательное подтверждение.
- Отдельный окончательный прогон затронутой области: **5 файлов, 156 тестов прошли** — `FluentApi`, `FluentAuthoring`, `FluentValidation`, `BuilderScopes`, `ModelContracts`.
- По итоговому подтверждению параллельной задачи: format/lint/typecheck прошли; coverage — 458 тестов и 100% всех метрик; Node policies — 2, performance — 4, compatibility — 48. Сборка, native import map в Chromium/Firefox/WebKit и SSR прошли.
- Скриншоты macOS обновлены после визуального просмотра в параллельной задаче. Linux-эталоны не обновлялись и не проверялись: Linux runtime недоступен.
- Финальный замер опубликованного формата пакета (`demo/BuildSize.js`): все определения — **100 084 Б raw / 30 376 Б gzip**, крупнейшее семейство MixedChart — **21 948 Б gzip**. Это отдельный package build после всех исправлений; сравнительная таблица выше фиксирует более ранний замер непосредственно из исходников. Существенного уменьшения полного пакета оба замера не показывают.
- Последняя сравнительная consumer-сборка обоих entries прошла; `git diff --check` прошёл. Измерение включает последующие совместные исправления: полный пакет вырос на 59 Б gzip относительно снимка начала задачи.

## Граница результата

Унификация уменьшает повторение и отдельные зависимости. Сокращение полного пакета в разы не подтверждено. Для более сильного сокращения потребителю прежде всего нужно импортировать только нужные определения; текущая архитектура уже допускает это. Выделение режима без взаимодействий или отдельного API без fluent-builder может дать следующий шаг, но его следует проектировать и измерять отдельно, сохраняя существующий API.
