# Матрица продуктовой проверки

Объект: README и веб-демо Orchid Charts на компьютере и телефоне.
Задача посетителя: понять пользу, попробовать свои данные и получить рабочий код.
Apple и подход Laravel задают два ведущих критерия: качество видимого результата
и удобство пути разработчика. Ниже — наши выводы из опубликованных принципов;
это не реальные отзывы или одобрения указанных людей.

## Итоговая структура

Демо: продуктовый hero → виды графиков и сценарии → объединённый блок
«Learn It Once. Use It Everywhere.» со своими данными, кодом и ссылкой на установку
→ короткая область применения. Ссылка из hero ведёт прямо к конструктору. README: результат → первый график → три конкретные
выгоды → настройка → типы → обновление и экспорт → область применения → документация.

Внешние имена в этой матрице нужны для прослеживаемости подходов. Они не используются
в публичных текстах как рекомендация продукта. Сравнения библиотек не добавляются
в README и демо.

## Проверка

- Сборка демо, линтеры затронутых файлов и проверка ссылок документации.
- Браузерные тесты изменения данных и типа, обработки ошибок, темы и копирования.
- Проверка скопированного JavaScript на отдельном контейнере и экспортированного SVG.
- Визуальная проверка в светлой и тёмной теме, на компьютере и при ширине 320/390 px.
- Проверка клавиатурного ввода, фокуса, инспекции графика и отсутствия горизонтального
  переполнения страницы.

## Результат проверки реализации

- `npm run build:demo`: сборка успешна.
- `npx vitest run --project site-chromium test/Demo.test.js test/DemoTry.test.js test/Documentation.test.js`:
  37 тестов прошли, включая сохранение SVG при обновлении, восстановление после
  неверного ввода, разную длину данных, смену типа и темы, копирование и очистку.
- `node --test test-node/Documentation.test.mjs`: 2 теста публикации документации
  и локальных ссылок прошли.
- ESLint, Stylelint и Prettier для затронутых файлов прошли.
- В Chromium при ширине 1440, 390 и 320 px проверены ввод с Enter, переключение
  типа, светлая/тёмная поверхность, навигация по значениям стрелками, фактическое
  содержимое буфера обмена и загрузка `monthly-revenue.svg`.
- SVG разобран как XML: ошибок нет, новые значения присутствуют, тёмная тема
  сохраняет вычисленные цвета текста. Скопированные рецепты Line и Bar отдельно
  выполнены на новом контейнере: каждый создал один график с введёнными данными.
- Скриншоты нового блока просмотрены на компьютере и телефоне. Горизонтального
  переполнения страницы нет; длинный код прокручивается внутри своего блока.
- В README, публичных руководствах, демо и документе позиционирования нет названий
  конкурирующих библиотек. Обоснование выбора строится на задачах Orchid.

Это подтверждает работу сценария и согласованность подачи. Рост использования
и понятность для новых разработчиков нужно оценивать по реальным внедрениям;
браузерные проверки не заменяют исследование пользователей.
